# TouchHop

**画面にタッチすると、ポインタがその位置へ。**

[English](README.md) · [简体中文](README.zh-CN.md)

TouchHop は、外部タッチスクリーンの絶対座標マウス入力を、選択したディスプレイに割り当てる小さな macOS アプリです。ポインタが Mac の内蔵ディスプレイにあっても、外部ディスプレイに触れるだけで、その位置へ移動してマウス操作を実行します。

## 対応範囲

現在は、実機で確認した特定の USB コントローラに対応しています。すべてのタッチスクリーンに使える汎用ドライバではありません。

| 項目 | 対応範囲 |
| --- | --- |
| USB ベンダー / 製品 ID | `0x056A` / `0x8191`、製品名 `TOUCH` |
| インターフェイス | USB Generic Desktop / Mouse、絶対座標 X/Y |
| レポート | ID `7`、3 ビットのボタン情報、16 ビットのリトルエンディアン X/Y、8 ビットのホイール情報 |
| 対象画面 | 選択した外部ディスプレイ 1 台。画面の UUID を保存 |
| 必要な OS | macOS 14.0 以降 |
| 実機確認 | Apple M4、macOS 27.2、2 つのマウスインターフェイスを持つ外部タッチスクリーン |

内蔵画面から外部画面へのタッチ移動、四隅と中央付近の位置、およびアプリ再起動後の設定復元を確認しています。ほかのコントローラ、Intel Mac、ほかの macOS バージョンは未検証です。座標の上限はデバイスの情報から取得するため、検証時の画面解像度には固定していません。

## 主な機能

- ポインタが別の画面にあっても、タッチした位置へ直接移動。
- 1 本指の押下・解放・ドラッグと、ダブルクリック用のクリック回数処理。
- 90°、180°、270° の座標回転。
- 単独キーまたはキーの組み合わせで画面を切り替え。初期設定は右 Command。
- 各画面で最後に離れた位置へ戻り、虹色のリングと拡大ポインタで位置を表示。
- メニューバーに常駐し、設定ウインドウを閉じても動作を継続。
- 英語、簡体字中国語、日本語のインターフェイス。
- ネットワーク通信、テレメトリ、カーネル拡張、管理者サービスは使用しません。

ダブルクリックとドラッグは実装済みですが、それぞれの独立した実機受け入れテストは行っていません。マルチタッチジェスチャ、スクロール、ペン入力、任意の HID レポート形式には対応していません。

## ビルド

Apple の Xcode Command Line Tools が必要です。未導入の場合は、次を実行します。

```sh
xcode-select --install
```

リポジトリを取得してビルドします。

```sh
git clone https://github.com/chenyongwei/touchhop.git
cd touchhop
./scripts/build.sh
./scripts/test.sh
```

出力先は `build/TouchHop.app` です。ホストのアーキテクチャ（`arm64` または `x86_64`）を使用し、macOS 14.0 以降を対象にします。`TOUCHHOP_ARCH` で変更できますが、クロスコンパイルだけでは実機の動作確認にはなりません。

開発用のアドホック署名を使用しており、Apple の公証は受けていません。ビルドスクリプトはアプリのインストールやシステム権限の変更を行いません。

## 使い方

1. 同じタッチパネルを使用するほかのタッチ補正アプリを終了します。
2. `build/TouchHop.app` を「アプリケーション」にコピーして開きます。
3. 「タッチスクリーン」で対象の外部ディスプレイを選択します。
4. 「権限と状態」の「操作を許可」から、マウス操作に必要な権限を許可します。macOS のバージョンによっては「アクセシビリティ」または「Device Control and Data Access」と表示されます。システムの認証はご自身で行ってください。
5. 「入力監視を許可」から入力監視を許可します。再起動を求められた場合はアプリを再起動します。
6. 権限と対象画面が利用可能になると、初期設定ではタッチ位置の補正が有効になります。内蔵画面にポインタを置き、外部画面の空白部分をタッチして位置を確認します。
7. 必要に応じて「タッチの向き」を変更し、四隅と中央を再確認します。

メニューバーの「タッチ位置の補正」は、有効な間はチェック付きで表示されます。クリックしてチェックを外すと無効になり、再度クリックすると有効になります。手動で無効にした設定は、アプリの再起動後も保持されます。無効化または終了するとインターフェイスを解放し、macOS の標準処理に戻ります。

ログイン時に起動するには、「システム設定 → 一般 → ログイン項目」に TouchHop を追加します。保存した対象画面と必要な権限が利用できる場合、有効な設定を起動後に復元します。

公開版 TouchHop は、以前のローカル試作版「外屏触控定位」とアプリの識別情報が異なるため、権限と設定は別々です。TouchHop を有効にする前に試作版を終了してください。本リポジトリは既存のインストールを置き換えません。

## 画面切り替えとポインタ表示

右 Command を単独で押して離すと、次の画面へ移動します。2 画面の場合は交互に切り替え、各画面で最後に離れた位置へ戻ります。記録がない画面では中央へ移動します。3 画面以上の場合は、メイン画面を先頭とする順番で循環します。

通常のマウス移動とタッチによる画面移動の両方で位置を更新します。各物理画面につき最後の 1 点だけをメモリに保持し、アプリ終了時に消去します。画面配置や解像度の変更、再接続後は相対位置を使って復元します。移動の軌跡は保存しません。

「画面切り替えショートカット」で表示中のキーをクリックすると、単独キーまたは組み合わせを登録できます。修飾キー単独の場合は、離すと確定します。Esc でキャンセルし、「初期設定に戻す」で右 Command に戻せます。Esc と Caps Lock は割り当てられません。

左右の Command は区別されます。修飾キーをほかのキーやマウス操作と組み合わせた場合、画面切り替えは発生しないため、Command+C や Command+V は通常どおり使用できます。文字キーやスペースを単独で割り当てると、そのキーの通常の文字入力を置き換えます。修飾キーを追加した通常の用途は維持します。

切り替え後は、約 1 秒間、虹色のリングと拡大ポインタを表示します。黒と白の二重の縁取りにより、明るい背景、暗い背景、近い色の背景でも輪郭を見分けやすくしています。表示はクリックを妨げず、自動的に消えます。システムのポインタサイズは変更しません。macOS の「視差効果を減らす」が有効な場合、リングの動きを止めて表示します。「プレビュー」で位置を動かさずに確認できます。

物理マウスでドラッグ中の場合は、ボタンを離してから切り替えてください。タッチでドラッグ中の場合、TouchHop 自身が押下したボタンを解放し、その指が離れるまで入力を抑制して、画面に引き戻されるのを防ぎます。

## メニューバーと表示言語

設定は「タッチスクリーン」「画面切り替えショートカット」「権限と状態」に分かれています。接続数や受信状況は「接続の詳細を表示」で確認できます。

TouchHop は Dock を使用せず、メニューバーに常駐します。ウインドウを閉じるか Command+W を押しても、タッチ位置の補正、ショートカット、位置の記録は動作を続けます。メニューバーのポインタアイコンから設定を開き直したり、機能を切り替えたりできます。「TouchHop を終了」でアプリを終了します。設定ウインドウがアクティブなときは Command+Q でも終了できます。

アイコンが見つからない場合は、システム設定の「メニューバー」で表示が許可されていることを確認してください。Frost などを使用している場合は、TouchHop を Visible（常時表示）に入れ、見えているアイコンの近くへ移動します。混雑しているメニューバーでは、常時表示に指定していても表示範囲から外れることがあります。アプリをもう一度開いても設定を表示できます。

1 つのアプリに英語、簡体字中国語、日本語を含みます。macOS の言語設定に従い、「システム設定 → 一般 → 言語と地域」で TouchHop 専用の言語を指定することもできます。変更後はアプリを終了して開き直してください。未対応の言語では英語に戻ります。表示言語を変えても、対象画面、向き、ショートカット、有効・無効の設定は保持します。

## 検証とプライバシー

自動テストは、レポート解析、座標変換、ショートカット、画面ごとの位置記録、翻訳リソースの完全性と書式引数を含む 87 項目です。HID デバイスの取得、権限の要求、イベント監視の開始、入力イベントの送信は行いません。GitHub Actions でビルド、テスト、開発用 ZIP の生成を行います。CI は実際のタッチパネル、権限、ログイン時の起動を検証しません。

保存するのは対象画面、向き、有効・無効、ショートカットなどの設定です。入力履歴や文字列、タッチの軌跡を記録せず、ネットワークにも送信しません。対象ディスプレイが利用できない場合に、タッチを内蔵画面へ振り向けることはありません。
